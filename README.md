# Выкладка agregatory.pro на reg.ru

Каждые 30 минут забирает код сайта из `iamsitnikov-prog/food-delivery-site-10`,
собирает его, подкладывает `.htaccess` из этого репозитория (файл `htaccess`)
и выкладывает на хостинг reg.ru по FTP. Запустить вручную: Actions → «Выкладка
agregatory.pro на reg.ru» → Run workflow.

- `htaccess` — правила Apache (страницы пререндера, 404, редиректы). Блок
  редиректа на https закомментирован: включить после выпуска SSL-сертификата.
- `check.sh` — проверка сайта после выкладки.
- `api/crm.php`, `api/crm-lib.php`, `api/docs-auth.php` — раздел «Заявки» (CRM) в кабинете /dokumenty (с 21.10.2026):
  все заявки (форма, чек-листы, оплаты, ручные) в `api/data/crm/leads.json`, статусы, ответственные,
  комментарии, история; вход по тем же пин-кодам, что договоры; личные уведомления ответственной через бота заявок.
- `api/report.php` + `.github/workflows/report.yml` — раз в неделю (сб, 9:52 МСК) файл заявок
  (CSV для Excel) уходит в личный Telegram Юрия от бота заявок. Тестовые заявки Claude не включаются.
- `api/lead.php` — приём заявок с формы на нашем хостинге (с 11.10.2026). Каждая заявка:
  1. пишется в журнал `api/data/leads.csv` на хостинге (снаружи закрыт);
  2. уходит в Telegram: личный чат Юрия и рабочая группа (секреты `TG_BOT_TOKEN`,
     `TG_CHAT_ID` через запятую);
  3. уходит письмом от `info@agregatory.pro` на Яндекс и Gmail Юрия, копией Алисе
     и в ящик info@ (адреса в `api/lead.php`; секрет `LEAD_EMAIL_TO`, если задан, их заменяет);
  4. только если не сработали ни Telegram, ни почта — пересылается в старую функцию poehali.dev.
  Почта домена: ящик info@agregatory.pro на хостинге reg.ru, в DNS добавлены SPF
  и MX (mx1/mx2.hosting.reg.ru). Хостинг отправляет письма только от существующего ящика.
